# 🐝 PASIKA — Production Honey Store Platform

Повноцінна production-система інтернет-магазину натурального меду та продуктів бджільництва власної сімейної пасіки.

Платформа побудована на трирівневій архітектурі: клієнтський SPA-інтерфейс, захищений бекенд-сервер на Node.js / Express та реляційна база даних SQLite у режимі WAL з повною підтримкою транзакцій, системи резервування залишків, поштових сервісів (Нова Пошта, Укрпошта) та сповіщень у Telegram.

---

## 🏛️ Архітектура системи

```
Frontend (React 19 / Vite / Tailwind)
   │
   │  HTTPS / Cookie HttpOnly / JSON API
   ▼
Backend API (Node.js / Express 5)
   ├── 📦 Orders & Status Lifecycle (10 статусів, історія змін)
   ├── 🍯 Products & Category Catalog
   ├── 🛡️ Stock & Transactional Reservations (available = total - reserved)
   ├── 💳 Payments & Receipt Verification (/uploads/receipts/)
   ├── 🚚 Delivery Architecture (Multi-Account DeliveryProvider)
   │    ├── Nova Poshta API v2 (ТТН, міста, відділення, трекінг)
   │    └── Ukrposhta API (OpenAPI, трекінг, валідація)
   ├── 🤖 Telegram Notification Service (Multi-recipient, роли)
   ├── 🔎 Public Tracking (/track-order без витоку персональних даних)
   └── 🔐 Admin & Security (RBAC, scrypt, сесії, бекапи)
   │
   ▼
Database (SQLite WAL `pasika.db` з Foreign Keys)
```

## 🚀 Швидкий старт

### Вимоги
- **Node.js**: `>= 20.19.0` (або `22.x`)
- **npm**: `>= 10.x`

### 1. Встановлення залежностей та налаштування оточення
```bash
cp .env.example .env
npm install
```

### 2. Запуск у режимі розробки
```bash
npm run dev
```
- Клієнтська частина доступна за адресою: `http://localhost:5173`
- Бекенд API доступний за адресою: `http://localhost:3001` (Vite проксує `/api` на бекенд)

### 3. Автоматична верифікація та тести
```bash
# Запуск автоматизованого тест-сьюту (21 тест перевірки логіки production)
node scripts/test-production-upgrade.mjs

# Перевірка коду лінтером (0 помилок)
npm run lint

# Складання production-білда фронтенду
npm run build
```

### 4. Запуск у Production
```bash
npm run build
npm start
```
Сервер запуститься на порті `3001` (або `PORT` з `.env`), самостійно роздаючи як API, так і статичні оптимізовані файли з каталогу `dist/`.

## 📦 Склад та система резервування (Anti-Overselling)

Формула розрахунку доступного товару:
$$\text{available\_stock} = \text{total\_stock} - \text{reserved\_stock}$$

Клієнт **не може** замовити більше ніж $\text{available\_stock}$. Перевірка виконується:
1. При додаванні товару в кошик;
2. При збільшенні кількості товару (`+`);
3. При вході на сторінку оформлення замовлення (`/checkout`);
4. Безпосередньо перед створенням замовлення на бекенді в єдиній транзакції.

### Життєвий цикл резервування
1. **Створення замовлення** (`NEW` або `AWAITING_PAYMENT`):
   - `reserved_stock += qty`
   - `available_stock` зменшується
   - Фізичний `stock` залишається незмінним
   - Вноситься запис у таблицю `stock_reservations` зі статусом `ACTIVE`.
2. **Скасування замовлення** (`CANCELLED`):
   - Резерв автоматично звільняється: `reserved_stock -= qty`
   - Запис у `stock_reservations` переходить у статус `RELEASED`.
3. **Комплектація та відправка** (`PACKED`, `SHIPMENT_CREATED`, `SHIPPED`, `COMPLETED`):
   - Списання фіксується: `stock -= qty`, `reserved_stock -= qty`
   - Запис у `stock_reservations` переходить у статус `FULFILLED`.
   - Захист від подвійного списання гарантує, що подальші зміни статусу не змінюють залишок повторно.

---

## 📋 10 статусів замовлення

Кожне замовлення проходить через строго визначені статуси з фіксацією історії в `order_status_history`:

1. `NEW` — Нове замовлення (післяплата / готівка).
2. `PROCESSING` — Замовлення прийнято в роботу менеджером.
3. `AWAITING_PAYMENT` — Очікує оплати або перевірки чека.
4. `PAID` — Оплату підтверджено адміністратором.
5. `PACKED` — Замовлення надійно спаковано.
6. `SHIPMENT_CREATED` — Створено ТТН перевізника.
7. `SHIPPED` — Передано до служби доставки.
8. `DELIVERED` — Прибуло до відділення або вручено клієнту.
9. `COMPLETED` — Успішно виконано та закрито.
10. `CANCELLED` — Скасовано (резерви автоматично повернено на склад).

## 🔢 Номери замовлень та відстеження

- Усі номери замовлень генеруються сервером за порядком: `PAS-10001`, `PAS-10002`, `PAS-10003`...
- **Публічна сторінка відстеження**: `/track-order`
  - Клієнт вводить номер замовлення (наприклад, `PAS-10001` або `10001`).
  - Система показує статус, таймлайн історії замовлення, склад посилки, спосіб доставки та посилання на ТТН.
  - **Захист приватності**: Номери телефонів, email та особисті адреси покупця **ніколи** не віддаються у публічному ендпоінті відстеження.

## 🚚 Служби доставки та мульти-акаунти

- Реалізовано архітектурний рівень `DeliveryProvider` з провайдерами:
  - `NovaPoshtaProvider`: пошук міст, відділень, розрахунок вартості, створення ТТН, живий трекінг, скасування ТТН.
  - `UkrposhtaProvider`: пошук міст та відділень через класифікатор, перевірка API, трекінг.
- **Мульти-акаунти відправників**:
  - В адмінці підтримується додавання кількох акаунтів (наприклад, окремо для різних складів чи відправників).
  - API-ключі зберігаються надійно в базі даних та маскуються при передачі на клієнт (`••••••••••••••••`).
- **Перевірка ключів**:
  - Кнопка **[Перевірити API]** надсилає запит до поштової служби й показує реальний стан:
    - 🟢 *API працює*
    - 🔴 *API key недійсний*
    - ⚪ *API не підключено*

## 🐝 Реалістичний політ бджіл (Bee Flight System)

- Реалістична 3D-модель бджоли з анатомічними пропорціями (опушене черевце, напівпрозорі крильця, відблиски світла).
- Природна просторова траєкторія польоту (`cubic-bezier`), плавні нахили та глибина різкості (DoF blur).
- Плаваючі золотисті мікрочастинки пилку.
- Адаптивність: 1 дослідник на мобільних пристроях, 3 бджоли на десктопі.
- Повна підтримка системних налаштувань `@media (prefers-reduced-motion: reduce)`.
